# Итоги года — фронтенд

Персональный recap пользователя классифайда в виде **города**: каждая категория, в которой
человек что-то делал за год, становится районом. Чем больше действий — тем выше дома.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
```

| Команда          | Что делает                          |
| ---------------- | ----------------------------------- |
| `npm run dev`    | dev-сервер Vite с HMR               |
| `npm run build`  | typecheck + production-сборка в `dist` |
| `npm run lint`   | ESLint с типизированными правилами  |
| `npm run format` | Prettier по `src`                   |

## Пользовательский путь

1. **`/`** — выбор тестового профиля. Четыре профиля с разными архетипами, включая намеренно
   «маленький» город Кирилла — он показывает, что сценарий не разваливается на слабой активности.
2. **`/generate/:profileId`** — сборка города. Шаги проговаривают, **что именно система посчитала
   важным**, — это часть шоу, а не технический лоадер.
3. **`/recap/:profileId`** — шесть глав. Каждая достраивает свой район и может вручить ачивку.
   Финальная глава раскрывает город целиком и переключает его в режим исследования.

Линейная история идёт первой намеренно: свободная карта с самого начала убивает досматриваемость,
а бизнес-задача требует, чтобы recap **досмотрели до конца**. Исследование открывается как награда.

## Ключевые решения

**Цвета.** Четыре брендовых цвета Авито сняты пипеткой с логотипа в PDF кейса
(`#05E061`, `#00AAFF`, `#FF4154`, `#9C61E7`), пастельные `#E8DBF6` / `#BADAFB` — с плашек оттуда же.
Девять районов разведены по этим четырём тонам через светлоту (`shared/lib/palette.ts`), поэтому
город остаётся в палитре и не превращается в радугу. Зелёный — единственный цвет действия на экране.

**Тёмная тема.** Жанр recap читается на тёмном, город на нём светится. Публичная share-card, наоборот,
светлая: она уходит наружу, где тёмная тема продукта уже не действует.

**Воспроизводимость.** Застройка целиком детерминирована: `mulberry32` от `recap.seed`
(`shared/lib/random.ts`), никакого `Math.random()`. Тот же профиль + та же версия правил = тот же
город на любой машине. Версия правил и сид показаны в подвале итогов.

**Приватность.** Приватный recap подробнее публичной карточки намеренно. В share-card уходят только
силуэт, название города, роль и число районов — ни категорий, ни счётчиков, ни цен. Силуэт строится
из сида, а не из активности, поэтому по нему нельзя восстановить поведение. Что входит и что не
входит — показано пользователю прямо в модалке.

**Объяснимость.** Требование ТЗ «объяснить, почему пользователь получил именно такой recap» закрыто
в интерфейсе: у роли и стиля есть кнопка «Почему я такой?», у каждой ачивки — раскрывающийся список
фактов, которые её зажгли.

**Возврат в продукт.** Незавершённые сценарии — это стройки на окраине города. Каждая строка панели
«Что не достроено» несёт конкретное следующее действие, а не абстрактное «перейти на Авито».

## Архитектура

```
src/
├── app/                  роутер и корневой компонент
├── pages/
│   ├── profiles/         выбор тестового профиля
│   ├── generating/       сборка города
│   └── recap/            главы + финальный экран, панели итогов
├── widgets/share-card/   публичная карточка
├── entities/city/        изометрический рендер города
│   ├── layout.ts         раскладка районов по сетке (slice-and-dice) и этажность
│   └── CityCanvas.tsx    отрисовка на canvas, анимация роста, пикинг районов
└── shared/
    ├── api/              данные (сейчас фикстуры, дальше — бэкенд)
    ├── lib/              палитра, детерминированный random, склонения
    ├── theme/tokens.css  переменные дизайн-системы
    └── types/recap.ts    контракт «Итогов года»
```

Город рисуется на `<canvas>`: 196 клеток с отдельными зданиями — это сотни DOM-узлов, если делать
на элементах. Наведение работает через offscreen-буфер пикинга, где индекс района закодирован
в красный канал пикселя, — точное попадание по зданию без геометрических вычислений.

## Данные и переход на бэкенд

Сейчас источник — фикстуры в `shared/api/mock/fixtures.ts`. Формат уже совпадает с будущим API,
меняются только тела двух функций в `shared/api/recap.ts`:

```
GET /api/v1/profiles        -> Profile[]
GET /api/v1/recap/:profile  -> Recap
```

Полный контракт — в `shared/types/recap.ts`. Фронт ничего не досчитывает: каждая цифра на экране
имеет источник в ответе. `share` района всегда производная от `actions`, поэтому площадь квартала
и число в легенде не могут разойтись.

## Линтеры

- **ESLint** с `recommendedTypeChecked` — типизированные правила ловят реальные ошибки
  (плавающие промисы, `await` без промиса), а не только стиль. Дополнительно запрещён явный `any`
  и включён единый стиль импорта типов. `eslint-config-prettier` идёт последним и гасит конфликты
  с форматтером.
- **Prettier** — форматирование, чтобы стиль не обсуждался на ревью.

## Ограничения MVP

- Данные активности подготовлены заранее; реальных пользователей и переписок нет.
- Кнопки CTA («Достроить районы», «Скопировать ссылку») — заглушки: настоящие ссылки появятся
  вместе с интеграцией в продукт.
- Город рисуется на сетке 14×14; для профилей с сильно большей активностью сетку нужно расширять.
